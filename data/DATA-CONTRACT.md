# חוזה הנתונים — מרכז בקרת ריצות

הנתונים בתיקייה הזו הם **קפואים** (fixtures סטטיים). אין שרת, אין DB, אין מפתחות API.
המבנה זהה למבנה האמיתי במערכת שלנו, כך שהדשבורד שתבני יוכל להתחבר לשרת אמיתי בהמשך בלי לשנות את שכבת התצוגה.

## קבצים

| קובץ | תוכן |
|---|---|
| `runs.json` | רשימת כל הריצות (13) — מה שמזין את מסך הסקירה |
| `runs/<run_id>.json` | פירוט מלא של ריצה בודדת — מה שמזין את מסך הריצה |

## מושגי יסוד

- **ריצה (run)** — צוות סוכני AI שמבצע משימה אחת מתחילתה ועד סופה.
- **צומת (node)** — סוכן בודד בתוך הריצה. לכל צומת תפקיד, מודל ועלות משלו.
- **אופרציה (operation)** — קריאת מודל בודדת. צומת יכול לייצר כמה אופרציות.
- **תקרה (ceiling)** — סכום התקציב שאושר לריצה. **התקרה יכולה לעלות באמצע ריצה** אם מנהל אישר הרחבה.

## סכום כסף — קרא בעיון

כל שדה שמסתיים ב-`_usd` הוא **מחרוזת** ולא מספר (למשל `"0.712900"`), בדיוק כמו ב-API האמיתי.
זה מכוון: מדובר בכסף, וייצוג עשרוני בינארי מאבד דיוק. אל תמירי ל-`Number` לצורך חישוב וסכימה.

## `runs.json`

```jsonc
{
  "runs": [
    {
      "run_id": "run-2c91e7",
      "title": "סקירת רגולציית פרטיות באיחוד האירופי",
      "requested_by": "מנהל המערכת",
      "status": "pending | running | completed | partial | failed",
      "outcome": "succeeded | partial | failed | null",   // null בזמן ריצה
      "initial_budget_usd": "0.350000",    // התקרה שאושרה בהתחלה
      "approved_budget_usd": "0.950000",   // התקרה הנוכחית (יכולה להיות גבוהה יותר)
      "spent_usd": "0.712900",
      "started_at": "2026-08-18T11:02:18Z",
      "ended_at": "2026-08-18T11:19:44Z",  // null אם עדיין רצה
      "agent_count": 4,
      "cost_is_complete": true             // ראי "עלות ידועה וחלקית" למטה
    }
  ]
}
```

> `status` הוא מצב הריצה. `outcome` הוא תוצאת האיכות. **הם לא אותו דבר** — ריצה יכולה
> להסתיים (`completed`) והתוצאה עדיין להיות חלקית, וריצה יכולה להצליח (`succeeded`)
> אחרי שאיכותה הורדה כדי להיכנס לתקציב.

### עלות ידועה וחלקית — `cost_is_complete`

כשהערך הוא `false`, המערכת **אינה יודעת כמה הריצה עלתה בפועל**. זה קורה כשפעולה
שוריינה מול התקציב והתהליך מת לפני שהחיוב סוכם: ייתכן שהספק חייב אותנו וייתכן שלא.
במקרה כזה `spent_usd` הוא **חסם תחתון בלבד** — העלות האמיתית שווה לו או גבוהה ממנו.
המערכת לא מנחשת ולא משלימה את הערך לבד; ההכרעה היא צעד אנושי.

## `runs/<run_id>.json`

מכיל את כל שדות הריצה מ-`runs.json`, ובנוסף:

### `nodes[]` — הסוכנים בריצה

```jsonc
{
  "node_id": "n1",
  "agent_name": "חוקרת רגולציה",
  "role": "research | analysis | reporter | critic | team_lead | custom",
  "tier": "orchestrator | worker | critic",
  "model": "claude-sonnet-4-6",   // null אם הצומת לא רץ
  "status": "pending | running | succeeded | failed",
  "cost_usd": "0.402300",
  "started_at": "...",            // null אם לא התחיל
  "ended_at": "...",              // null אם לא הסתיים
  "visible_summary": "..."        // null אם אין
}
```

### `operations[]` — קריאות המודל

```jsonc
{
  "operation_id": "01H2C91A:t1",  // הסיומת :t<N> = מספר התור בקריאה
  "node_id": "n1",
  "estimated_usd": "0.180000",    // כמה הוערך מראש
  "actual_usd": "0.230500",       // כמה עלה בפועל; null אם לא סוכם
  "settled": true,                // false = שוריין ולא סוכם, העלות לא ידועה
  "usage": {
    "input_tokens": 6310,
    "output_tokens": 6100,
    "cache_read_tokens": 22800,
    "cache_creation_tokens": 0,
    "web_search_count": 5,
    "max_tokens_cap": 2000,       // התקרה שנאכפה על הפלט
    "max_searches_cap": 5
  }
}
```

> `operation_id` יכול להופיע כמה פעמים לאותו צומת עם סיומות `:t0`, `:t1` — אלה **תורים
> עוקבים של אותה קריאה**, לא קריאות כפולות. סכימה שלהם היא עלות הצומת.

> באופרציה עם `"settled": false` גם `actual_usd` וגם `usage` הם `null` — לא קיבלנו
> תשובה מהספק, ולכן אין לנו נתוני שימוש ואין לנו עלות.

### `events[]` — מה קרה בריצה

```jsonc
{ "at": "2026-08-18T11:09:55Z", "type": "approval_resolved", "payload": { ... } }
```

סוגי אירועים שמופיעים בנתונים:

| `type` | משמעות |
|---|---|
| `budget_reserved` | שוריין תקציב לפעולה |
| `budget_overrun_80` | הריצה עברה 80% מהתקרה |
| `budget_hard_stop_95` | הריצה עברה 95% — עצירה קשה |
| `budget_exhausted` | התקציב נגמר; צמתים שנותרו לא הופעלו |
| `budget_overrun_detected` | **ההוצאה בפועל עברה את התקרה** |
| `budget_ceiling_extended` | התקרה הועלתה |
| `approval_requested` | נשלחה בקשת אישור להרחבת תקציב |
| `approval_resolved` | הבקשה אושרה |
| `approval_denied` | הבקשה נדחתה (או פג הזמן) |
| `execution_cap_downgraded` | **איכות הורדה במכוון** כדי להיכנס לתקציב |
| `web_search_performed` | בוצעו חיפושי רשת |
| `llm_call` / `llm_call_failed` | קריאת מודל הצליחה / נכשלה |
| `process_terminated` | התהליך מת באמצע קריאה |
| `budget_reservation_unresolved` | **שוריין תקציב ולא סוכם — לא ידוע אם חויבנו** |

### `budget_timeline[]` — היסטוריית התקרה

```jsonc
[
  { "at": "2026-08-18T11:02:18Z", "ceiling_usd": "0.350000", "reason": "initial_approval" },
  { "at": "2026-08-18T11:09:55Z", "ceiling_usd": "0.950000", "reason": "mid_run_extension_approved" }
]
```

## על הנתונים

הנתונים הם מדגם אמיתי מהמערכת שלנו, ולא נתוני הדגמה מסודרים. הם כוללים ריצות במצבים
שונים — כאלה שהסתיימו כרגיל, כאלה שלא, וכאלה שלגביהן המערכת עצמה אינה יודעת מה
בדיוק קרה — ושדות `null` בכל מקום שבו הם אפשריים.
